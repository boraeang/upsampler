# CLAUDE.md

## Project Specification

The full specification for this project is at:
`docs/claude_code_prompt_private_assets_frequency_v2.md`

Read it in full before implementing anything. It contains:
- Architecture (5-stage pipeline)
- Four pluggable smoothing models (AR(1), MA(q), Threshold AR(1), NoSmoothing)
- Asset class presets (PE, Infrastructure, Credit, Hedge Funds, Real Estate)
- API design, testing strategy, and build order
- Decision priorities, fallback mechanisms, and sanity anchors

## Decision Priorities (always apply)

1. Statistical validity > architectural purity
2. Numerical stability > theoretical elegance
3. Robustness to small samples > asymptotic correctness
4. Interpretability > marginal accuracy gains

## Rules

- Python 3.10+, type hints throughout
- Dependencies: numpy, scipy, pandas, statsmodels only (no PyMC/Stan/MCMC)
- NumPy-style docstrings on every public function
- Write and run tests before moving to the next module
- Every stage must validate its outputs before passing downstream
- Use `uncertainty_mode` and `FallbackPolicy` as specified in the prompt

Settled in step 5 (do not re-derive): the numpy signature backend is exact for
piecewise-linear paths (tensor exponential + Chen's identity) and is the ONLY
backend here, verified by shuffle/Chen/reparametrisation identities rather than
a library. PathSpec(level_channel='simple') makes the level-1 signature term
equal F_Q EXACTLY, which is what makes step 6's nesting test exact; basepoint
must stay True for that. keep_sigs='linear' exempts the time channel.

Settled in step 6 (do not re-derive): time-only signature terms are
STRUCTURALLY CONSTANT (time is rescaled to [0,1] on every window, so S(0)=1,
S(0,0)=1/2) and are dropped from the regressors — that is what makes the
nesting exact. Consequently the spec's multiplier_terms='time' is degenerate
(collinear with s_lag1); multiplier_terms='all' is the non-degenerate version.
The ridge penalty exempts the intercept and s_lag1; alpha uses sklearn's
ElasticNet scaling (n*alpha on the normal-equation diagonal).

Settled in step 7 (do not re-derive): once a quarter has CLOSED, no further
public factor data about it can arrive, so its nowcast does not move with the
calendar — evolution is event-driven (h=2 -> h=1 when the previous quarter
publishes), which is why as_of_offsets_days=(0, 30) is the right default and
extra offsets add nothing. Offset 0 is the only one that reaches h=2, because a
~100-day publication lag leaves only a ~9-day window with two unpublished
quarters. Nowcasting the OPEN quarter is unsupported: partial-quarter factor
aggregates are not comparable to the full-quarter aggregates models train on.

Settled in step 8 (do not re-derive): allow_provisional estimates Stages 1-2 on
published rows ONLY, then extends the desmoothed series across the provisional
tail with the FITTED filter (every smoothing filter here is causal, so the
published prefix is unchanged). Stage 3's Chow-Lin nuisance params DO see the
provisional tail — unavoidable, since the aggregation constraint must hold on
those rows too; recorded in disaggregation.diagnostics['estimation_window'].
The provisional mask travels in returns.attrs['provisional_mask'], set by
to_pipeline_returns(); allow_provisional=True without it raises.

Settled in step 4 (do not re-derive): ar1_bayesian fits RAW QUARTERLY
observations, so no lambda conversion is needed in the shipped configuration.
convert_lambda_to_quarterly() in models/structural.py holds the two conversions
that do exist, with derivations; the rolling-annual case must be declared
explicitly because it is undetectable from the index, and lambda_a**(1/4) is
badly wrong there (0.908 -> 0.976 instead of 0.60).
